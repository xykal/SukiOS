Status: **alpha, belum untuk distribusi**. Ditujukan untuk uji di perangkat nyata.
Isi rilis ini adalah tindak lanjut uji perangkat v0.3.1-alpha: tampilan dinilai kurang,
dan aplikasi pihak ketiga terbuka layar penuh.

## 1. Tampilan — Aurora v2

- Palet Aurora dikembalikan: dasar `#0B0D12`, permukaan `#12151D` / `#1A1F2B` / `#242A38`,
  krom `#1F2532`, teks `#F2F4F8`. Aksen ungu `#7C5CFF` -> teal `#35D0BA`.
- 6 preset aksen (Aurora, Laguna, Mekar, Azur, Bara, Mint). Setiap aksen punya tiga turunan
  yang dihitung untuk keterbacaan: `fill` (isi tombol), `on` (teks di atas fill), `text`
  (teks aksen di bidang gelap). Ungu murni tidak pernah dipakai untuk teks kecil.
- 6 wallpaper aurora (Aurora, Bara, Mint, Senja, Gletser, Noir) yang dibangun dari cahaya
  lunak berposisi pecahan, plus preferensi `wall_motion`.
- Kontras dibuktikan di CI (`ThemeContrastTest`): teks 4,5:1 di semua permukaan,
  teks aksen dan teks di atas isian tombol juga 4,5:1.
- Tipografi: Inter dan Plus Jakarta Sans disertakan sebagai berkas font (lisensi SIL OFL,
  salinannya di `app/src/main/assets/licenses/`).
- Ikon digambar sendiri sebagai path vektor (`SukiGlyphData.kt` dihasilkan
  `tools/gen_glyphs.py`, dicocokkan dengan berkas oleh `GlyphDataTest`). Tidak ada emoji.
- Jendela: bilah judul bergradien + garis rambut, pegangan geser, bayangan, animasi muncul,
  pratinjau snap saat bilah judul digeser. Tepi snap kiri/kanan 24 dp.
- Taskbar 54 dp, Start menu, panel pintasan, tray, dan desktop ditata ulang:
  panel jam + status mesin, ubin alat, grid aplikasi, menu tekan-lama per aplikasi.
- Ikon aplikasi pihak ketiga diseragamkan: ikon adaptif digambar ulang dari dua lapisannya
  (area aman 72 dp diisi penuh), ikon lama diberi plat gelap seragam.

## 2. Jendela mutlak untuk aplikasi pihak ketiga

- Satu jalur peluncuran: `am start --windowingMode 5 -n <pkg>/<activity>` lewat SukiShell
  (Shizuku, uid 2000). Semua argv diperiksa `ShellArgs` sebelum dikirim; tidak ada
  pemanggilan shell langsung dari UI selain Terminal.
- Kotak jendela awal dipilih sistem. SukiOS hanya mengoreksi bila tidak masuk akal
  (menutupi taskbar, keluar layar, di bawah 320x220 dp) lewat `am task resize`
  (`WindowBounds.needsFix` / `clampInto`).
- Hasil **selalu diverifikasi**, tidak pernah diasumsikan. `dumpsys activity activities`
  diurai (`FreeformParse`, toleran terhadap bentuk dump Android 10/11/14) dan mode tugas
  aplikasi itu dibaca. Enam kesimpulan yang mungkin:
  | Kesimpulan | Artinya |
  |---|---|
  | `WINDOWED` | Terbukti berjalan sebagai jendela |
  | `UNVERIFIED` | Perintah terkirim, tugas belum terbaca di dump |
  | `FULLSCREEN` | Perangkat menolak mode jendela |
  | `RUNNING_FULLSCREEN` | Aplikasi sudah berjalan layar penuh sebelum diminta; Android tidak memindahkan tugas yang ada |
  | `BLOCKED` | Shizuku belum siap |
  | `FAILED` | Perintah gagal; keluaran mentah ditampilkan |
- Potongan dump mentah disimpan dan bisa disalin dari Setelan > Jendela supaya klaim
  bisa diperiksa sendiri.
- Daftar jendela aplikasi lain dibaca berkala dari sistem (`SukiTasks`, tiap 3 detik,
  hanya saat Beranda terlihat), bukan digambar sebagai jendela palsu.

## 3. Penyiapan otomatis (Shizuku) yang diverifikasi

- Alur: Shizuku hidup -> izin (sekali per sesi binder) -> SukiShell tersambung ->
  jalankan `SetupPlan` -> verifikasi -> uji jendela.
- Idempoten: hanya langkah yang belum terpenuhi yang dijalankan. Kunci setelan yang baru
  dikenal Android 12L+ (`enable_non_resizable_multi_window`, `enable_sizecompat_freeform`)
  hanya dikirim pada SDK yang sesuai, ditandai opsional.
- Keberhasilan langkah diperiksa dengan API Android (`Settings.Global`, `Settings.Secure`,
  `canDrawOverlays`, status role HOME), **bukan** dengan mempercayai kode keluar perintah.
- Uji jendela memakai `ProbeActivity` milik SukiOS sendiri: dibuka dengan
  `--windowingMode 5`, lalu melaporkan dari dalam apakah `isInMultiWindowMode` benar,
  beserta lebar/tinggi layar yang dilihatnya. Hasilnya disimpan di preferensi, jadi
  kalimat "Jendela aktif" hanya muncul bila uji itu pernah lulus di perangkat ini.
- Bila aplikasi sudah berjalan layar penuh, pengguna ditawari menghentikannya dulu.
  Tidak pernah dimatikan diam-diam.

## 4. Keputusan produk

- Orientasi dikunci mendatar (`sensorLandscape`) untuk Beranda dan ProbeActivity.
  Alasannya: ini desktop, dan mode jendela diukur pada geometri mendatar.
- `minSdk` tetap 29. Mode jendela secara resmi dikenal sejak Android 12 (API 31);
  di API 29-30 hasilnya bergantung ROM dan dilaporkan apa adanya.
- versionCode 5, versionName 0.4.0.

## 5. Yang harus diuji di perangkat

1. Setelan > Jendela: jalankan persiapan otomatis, lalu **uji jendela**. Kalimat status
   harus berubah jadi "Jendela aktif" hanya bila uji benar-benar lulus.
2. Buka aplikasi pihak ketiga dari desktop/Start: harus muncul sebagai jendela mengambang.
   Bila tidak, kartu status harus menyebut alasannya (layar penuh / sudah berjalan /
   Shizuku belum siap), bukan diam.
3. Aplikasi yang sudah berjalan layar penuh: coba buka dari SukiOS, pastikan muncul tawaran
   "hentikan dulu" dan tidak ada proses yang dimatikan tanpa persetujuan.
4. Putar perangkat: tampilan harus tetap mendatar.
5. Geser bilah judul ke tepi kiri/kanan/atas: pratinjau harus sama dengan hasil snap.
6. Uji di dua perangkat bila mungkin (satu Snapdragon, satu ROM lain) dan kirim laporan
   diagnostik dari Setelan > Diagnostik.

## 6. Batas yang diketahui (jujur)

- Sebagian ROM pabrikan membuang dukungan freeform dari System UI; di sana perintah tetap
  dikirim tetapi hasilnya `FULLSCREEN`. Beberapa ROM menerapkan setelan freeform saat boot,
  jadi satu kali reboot bisa mengubah hasil.
- Tanda tangan APK: tanpa 4 secrets keystore, workflow rilis memakai debug key dan
  menandainya di rilis. Kunci debug tidak untuk distribusi.
- Kinerja belum diukur di perangkat: polling dump 3 detik dan gambar wallpaper bergerak
  adalah dua tempat pertama yang harus diperiksa bila terasa berat.
