## Addendum permintaan live wallpaper

Permintaan baru 2026-10-04: pengguna ingin SukiOS bisa memakai/menyetel **live wallpaper**.
Audit singkat sebelum implementasi:

- Tidak perlu permission baru: Android menyediakan picker lewat `WallpaperManager.ACTION_LIVE_WALLPAPER_CHOOSER` dan fallback `Intent.ACTION_SET_WALLPAPER`.
- Agar live wallpaper terlihat di belakang launcher, window Home perlu `FLAG_SHOW_WALLPAPER` / `windowShowWallpaper=true` dan background window transparan.
- UI Compose SukiOS selama ini menggambar wallpaper Aurora sendiri secara opak; jadi mode khusus perlu membuat root background transparan dan menggambar veil gelap transparan agar teks tetap terbaca.
- Batas jujur: SukiOS hanya membuka picker dan menampilkan wallpaper sistem di belakang desktop; memasang APK live wallpaper pihak ketiga tetap dilakukan oleh Android/Play Store/paket terpisah.

Status implementasi lokal:
- `WALLPAPER_SYSTEM_LIVE` ditambahkan sebagai id mode khusus (bukan preset Aurora).
- `Wallpaper()` menggambar `SystemWallpaperVeil` transparan saat mode ini aktif.
- `SukiHomeActivity` menyalakan `FLAG_SHOW_WALLPAPER`, theme memakai `windowShowWallpaper=true` dan background transparan.
- Setelan Tampilan mendapat kartu “Live wallpaper sistem” dengan tombol “Pakai” dan “Pilih live wallpaper”.
- `PureHelpersTest` ditambah untuk menjaga id live wallpaper tidak bertabrakan dengan preset.

Status: `LOCAL-FIXED`; perlu CI untuk label `CI-VERIFIED` dan uji perangkat untuk membuktikan live wallpaper benar-benar terlihat di ROM target.

Dampak:

- Status “jujur” di README jadi tidak dipercaya.

Saran fix:
1. Sinkronkan root `README.md` + `sukios/README.md` ke `v0.4.0-alpha`.
2. Jadikan `docs/release-notes/v0.4.0-alpha.md` sebagai checklist uji perangkat utama.
3. Tambahkan test/grep sederhana untuk mencegah instruksi install menyebut tag lama.

### MED

#### M-01 — Kepatuhan lisensi distribusi APK belum lengkap dan notices tidak konsisten

Bukti:
- `sukios/app/src/main/assets/licenses/` hanya berisi `OFL-Inter.txt` dan `OFL-PlusJakartaSans.txt`.
- `THIRD_PARTY_NOTICES.md` sudah mencatat Shizuku-API MIT dan Apache-2.0 untuk AndroidX/Compose/Kotlin, tetapi bagian Apache menyatakan salinan lisensi di APK belum dikerjakan.
- File yang sama masih punya kalimat lama: “SukiOS tidak menyertakan font … teks memakai font sistem”, padahal `SukiFonts.kt` dan `res/font/*.ttf` menunjukkan font dipaketkan.

Dampak:

Saran fix:

#### M-02 — `ProbeActivity` diekspor ke aplikasi lain

Bukti:
- `AndroidManifest.xml`: `.ProbeActivity` memakai `android:exported="true"`.
- `ManifestTest.only_the_home_and_probe_activities_are_exported()` justru mengunci bahwa Home + Probe harus exported.
- `IDEAS.md` #16 sudah mencatat usulan menjadikan Probe `exported="false"`.

Dampak:
- Risikonya tidak besar karena Probe tidak menyentuh data dan menutup otomatis, tetapi activity uji internal tidak perlu bisa dipicu aplikasi lain.
- Dalam skenario timing sempit, activity eksternal bisa mengganggu hasil probe yang sedang ditunggu.

Saran fix:
- Ubah Probe ke `exported="false"`, update `ManifestTest` menjadi “hanya Home exported”.
- Verifikasi di perangkat bahwa `am start --windowingMode 5 -n app.sukios/.ProbeActivity` dari uid shell tetap bisa membuka komponen tertutup, sesuai catatan backlog.

Status: `PROPOSED`, butuh uji runtime setelah diubah.

#### M-03 — Target sentuh belum konsisten 44 dp

Bukti cepat:
- `WinBtn`: 36 × 32 dp.
- `Taskbar.BarItem`: 42 dp.
- `Chip`: min 32 dp.
- `SukiSlider`: 28 dp.
- `SearchField`: 40 dp.
- `SideItem`: min 40 dp.

Dampak:
- Di HP kecil/mouse-less, tombol close/minimize/resize dan chip lebih sulit ditekan.
- Ini terutama terasa pada perangkat yang jadi target awal SukiOS: HP/tablet kecil.

Saran fix:
- Tentukan token `TOUCH_MIN_DP = 44` di theme/kit.
- Terapkan minimal 44 dp untuk kontrol interaktif utama; khusus window control bisa visual 32 dp tetapi hitbox 44 dp.
- Tambah test statis sederhana untuk pola `.size(width = 36.dp, height = 32.dp)` atau komponenisasi lewat satu helper.

Status: `PROPOSED`.

#### M-04 — i18n belum siap meski resource configuration menyebut `in` dan `en`

Bukti:
- `strings.xml` hanya 4 string.
- Heuristik sederhana menemukan puluhan teks UI hardcoded di Kotlin (`Txt("...")`, `Btn("...")`, `WinPanel("...")`, dll.).
- `defaultConfig.resourceConfigurations += listOf("in", "en")`, tetapi belum ada `values-in/` dan default string mayoritas masih di Kotlin.

Dampak:
- Produk masih Indonesia-only secara praktis.
- Migrasi sebagian bisa berbahaya bila Android Lint `MissingTranslation` dinyalakan tanpa strategi.

Saran fix:
- Pilih strategi: default English + `values-in` Indonesia, atau tetap Indonesia default sampai V1.
- Migrasi bertahap per layar; jangan set fatal MissingTranslation sampai cakupan cukup.

Status: `PROPOSED`.

#### L-02 — Cabang mati di `SukiWindowing`: resize initial saat bounds null tidak pernah jalan

Bukti:
- `WindowBounds.needsFix(null, ...)` mengembalikan false dan test mengunci perilaku itu.
- Di `SukiWindowing.openLocked`, blok lama `if (WindowBounds.needsFix(task.bounds, ...)) { val target = if (b == null) WindowBounds.initial(...) else ... }` membuat cabang `b == null` tidak terjangkau.

Dampak:
- Tidak merusak build, tetapi membingungkan pembaca: apakah null bounds harus dibiarkan atau diberi initial bounds?

Tindakan lokal:
- Dipilih aturan eksplisit **“null bounds = jangan tebak”**.
- Cabang `WindowBounds.initial(...)` yang tidak terjangkau dihapus dari `SukiWindowing.openLocked`; koreksi resize hanya berjalan bila `bounds != null` dan `needsFix(bounds)` benar.

Status: `LOCAL-FIXED`; perlu CI untuk label `CI-VERIFIED`.
